# 去 AI 味补充：ainovel-cli 判据 + 语句对照库

> 合并自 `refs/ainovel-cli`（「去 AI 味与自定义规则」：机械基线 + `anti-ai-tone.md` 语义判据 + 可覆盖规则层）与本仓库 `book/_analysis/` 语句对照库。与 Gate A–G、`banned-words.md`、三遍法**叠加**使用，不替代既有删除保护与 C 级禁动。

## 何时加载

- 文件模式去味（章节/正文路径）且需要「对照库替换」时：**必读**本文件。
- 用户提到「人味替换」「phrase bank」「对照库」「_humanized」时：必读。
- **清理 / 重构档（默认去味）**：本文件的对照库替换是**硬步骤**，不得因「map 零精确命中」或「已跑 Gate」而跳过。
- 仅检测档、或用户原话只要 Gate / 禁用词句式、明确说「不要对照库」时：可跳过替换协议，仍可参考下方机械基线与五类语义判据；报告须写 `对照库:跳过（用户豁免）`。

---

## 完成门禁（硬性）

文件模式清理/重构档，下列任一缺失则**去味未完成**，不得宣称「已去AI味 / Deslop 完成」：

1. 已按下文「替换协议」跑完**对照库遍**（精确 map + **逐句语义对齐**）。
2. 报告含：`对照库:已执行`、扫描句数、精确 map 命中/替换、语义对齐命中/替换、跳过/`[需复核]`、`{xx}` 回填。
3. 有 `_humanized` 产物（或用户授权的原地改 / 写后定稿覆盖）且改前备份路径已写明；写后定稿模式另须 `定稿覆盖:已执行`。

允许「替换数 = 0」，但必须证明已扫完：报告写 `语义扫描完成，无可替句（理由：…）`。只跑 Gate / `check-ai-patterns.js` / 标点归一 **不算**完成本步。

## 一、机械基线（ainovel-cli `rules.SystemDefaults`）

commit/收尾时按**字面**检查；与 `banned-words.md` 一级词并存，命中即处理（删或换），白名单真子串豁免规则不变。

### 禁用套句（ForbiddenPhrases）

| 套句 | 处理 |
|------|------|
| 某种程度上 | 删；改写为具体事实或选择 |
| 值得注意的是 | 删；直接写要交代的事 |
| 不知为何 | 删，或改成角色当下可见线索 |
| 五味杂陈 | 改成一个具体反应/动作 |

### 疲劳词阈值（章内上限；超过则压密度）

| 词 | 章上限 | 备注 |
|----|--------|------|
| 不禁 | 1 | |
| 竟然 | 1 | |
| 仿佛 | 2 | |
| 此外 | 1 | |
| 然而 | 2 | 口语优先「但/可」 |
| 一丝 | 2 | 情绪量词癖 |
| 一抹 | 2 | |
| 一缕 | 2 | |
| 宛如 | 1 | |
| 不由得 | 1 | |
| 像一 | 3 | 后段节拍词，放宽仍要控 |
| 沉默了 | 2 | |
| 没有说话 | 2 | |
| 几息 / 一息 | 3 | |
| 数息 | 2 | |

带变量的模式（「不是 X 而是 Y」等）仍归 Gate B / `anti-ai-writing.md`，不靠本表机械枚举。

## 二、语义判据五类（ainovel-cli `anti-ai-tone.md`）

机械层抓表面，本表抓质感。与现有 Gate 粗对齐：结构≈D/F，用词≈A/B，描写≈C，对话≈E，节奏/升华≈D/F/G。

### 1. 结构

- **三段式 / 排比三连**：连用三个对称短句造势。改法：留一句最有力的，其余改动作或细节。
- **整齐对称句堆叠**：段长、句式高度雷同。改法：长短交错。
- **章内编号小标题 / `##` 切割**：正文里 `一、二、三` 或 markdown 小标题切场景。改法：只留章标题，场景用空行过渡。

### 2. 用词

- **四字成语堆砌**：一串成语当描写。改法：一个具体动作/画面。
- **明喻套句**：「如同……一般」「宛如……似的」「仿佛……一样」反复。改法：精准动词、白描，或少数生活化比喻。
- **量词癖 / 虚词癖**：「一丝/一抹/一缕」配情绪；「不禁/竟然/不由得/仿佛」口头禅。改法：删缓冲，动作直接发生。
- **抽象大词**：「某种程度上」「值得注意的是」「不知为何」「说不清道不明」。改法：删，让位给事实。
- **对比定义句式**：「他要的不是 X，而是 Y」点题金句。改法：用具体动作/选择呈现。

### 3. 描写

- **抽象概述代替五感**：「环境很压抑」。改法：可触/嗅/听的细节。
- **情绪贴标签**：「他很紧张」。改法：身体反应与选择，不点名情绪。

### 4. 对话

- **角色同质化**：遮名无法分辨。改法：稳定句长、口头禅、潜台词比例。
- **过度解释动机**：角色或叙述者把心理和盘托出。改法：藏在选择与言外之意。
- **书面腔**：人人完整规整带逻辑连接词。改法：停顿、省略、答非所问。

### 5. 节奏与情感

- **事事交代完整**：不留想象空间。改法：该藏则藏。
- **强行升华 / 结尾点题**：章末人生感悟。改法：停在画面、选择或情绪余波。

## 三、自定义规则层（映射到本仓）

ainovel-cli：`~/.ainovel/rules/*.md`（全局）与 `./.ainovel/rules/*.md`（本书）自然语言偏好 → 归一化快照；`style/voice.md`、`style/anti-ai-tone.md` **追加**覆盖。

本仓等价约定（无需改源码）：

| 意图 | 本仓落点 | 优先级 |
|------|----------|--------|
| 本书写作标准 / 去味偏好 | `{书根}/设定/文风.md` | 高于本文件默认 |
| 机械放行字面片段 | `{书根}/.deslop-whitelist` | 与现有深扫/标点一致 |
| 作者长期文风习惯 | `.story/作者记忆/` + `prose_style` query | 低于当前请求与剧情保护 |
| 一次性本章要求 | 用户本轮指令 | 最高 |

指导性文本（文风、本文件判据）可追加；需要**机械强制**的禁词/阈值写进文风或白名单旁的明确清单，并在报告里写清来源。不引入假经历、不注水骗检测（Never inject 仍有效）。

## 四、语句对照库（book/_analysis）

### 数据源（按职责选用）

| 文件 | 用途 |
|------|------|
| `book/_analysis/ai_to_human_replacements.json` | **替换优先**：`map` 按 AI 表达键查 `replace_with[]`；`pairs[].human_expr` / `buckets_summary[].human_top` 为人味句（人名已作 `{xx}`） |
| `book/_analysis/ai_human_phrase_bank.json` | 全量：`buckets` + `curated_groups` + `replacement_pairs`；其中 `replacement_pairs[].human_expr` 人名已作 `{xx}` |
| `book/_analysis/phrase_bank_index.md` | 分类索引与精选示例表；快速人工扫类目 |

### 替换协议（禁止无脑全局替换）

> **核心判据（必须执行）**：对正文**逐句**判断——这句在说什么（对齐 `category` / `meaning`）？表里有没有**能表达同一个意思**的人味句？若意思一致且替换后不漂命题（条件/否定/情态/归属/比较方向不变），就从该组的 `replace_with` / `human_expr` / `human_top` **挑 1 条**换掉本句（或句内模板片段）；不一致则不换。禁止只做精确字符串命中就收工。

1. **先扫描再替换**：只处理正文中真实出现的 AI/模板串或语义同类句；未出现的键不要预替换。
2. **查表顺序（两层，缺一不可）**：
   - **A. 精确层**：`ai_to_human_replacements.json` 的 `map[原文片段]` → 有则从 `replace_with` **按语境挑 1 条**（兼顾人称、语气、前后句）。
   - **B. 语义层（硬步骤）**：精确层扫完后，**再**按句走一遍。把该句归到表内某一 `meaning`（震惊、强压情绪、不是A而是B、系统提示、突然转折…）；若句意与该类一致、能换而不丢信息，则从同 `meaning` 的 `replace_with` / `pairs[].human_expr` / `buckets_summary[].human_top` / phrase_bank 精选组 **挑 1 条**替换。无合适人味句或会漂义 → 不替，记入跳过理由，再交 Gate 润色或删。
3. **意思一致才换**：替换前后必须仍是「同一件事、同一判断方向」。只换壳，不换剧情、不换结论、不换谁对谁做什么。表内示例常带源书人名/细节——写入前剥掉无关细节，只保留与本句同义的人味骨架，再按第 4 条回填本书角色。
4. **按 category / meaning 选组**：情绪反应、表情动作、心理活动、叙事转折、人物出场、设定呈现、动作场面、环境氛围、态度口吻、节奏停顿——同类内换，不跨类硬套。
5. **`{xx}` 角色名回填（硬性）**：`human_expr` / `human_top` 里的人名已统一写成占位符 `{xx}`（`ai_*` / `replace_with` / `human_examples` 未改）。选用人味句写入正文前，**必须**把每个 `{xx}` 换成**本书**角色名，禁止把 `{xx}` 或源书角色名写进产物。
   - **角色名来源**（按序）：本章正文已出场名 → `{书根}/设定/角色/*.md` 文件名与卡内本名/别名 → `设定/关系.md` 表内角色 → 追踪/细纲里的当前 POV。缺名册时用本章主语/POV；仍无法判定则标 `[需复核：角色名]`，不硬填。
   - **多槽**：一句多个 `{xx}` 时，按语序对应「动作主体 / 被看对象 / 旁人」等，分别填不同角色；不要全句刷成同一个名字，除非原文语境就是同一人。
   - **人称**：回填后若章为第一人称，把「{角色}愣住」等改成「我愣住」等与 POV 一致的说法。
6. **改人称与语气**：表内多为第三人称口语示例；目标章若是第一人称/角色声线，替换后必须改到与上下文一致（与上条一并完成）。
7. **剧情保护优先**：会丢伏笔、钩子、因果、人物记忆、必要信息的命中 → 不替或降 AI 重写，标 `[需复核]`。
8. **密度**：同一人味短句（如「我靠」「行吧」）同章不要刷屏；疲劳词表与本协议同时生效。
9. **与 Gate 顺序**：先完成本对照库遍（精确 + 语义），再跑选定 Gate；Gate 中再遇模板句优先回表挑词，避免另造近义 AI 腔。**先 Gate 后宣称完成、却未跑语义层 = 未完成去味。**

### 精选方向速查（完整表见 phrase_bank_index.md）

| 类 | AI/模板倾向 | 人味方向 |
|----|-------------|---------|
| 震惊 | 瞳孔猛地一缩 / 空气凝固 | 愣住、脑子嗡了一下、吓我一跳 |
| 强压情绪 | 深吸一口气强压… | 压住火、先缓缓、骂一句 |
| 愤怒 | 怒火中烧 / 眼中闪过一丝怒意 | 火了、脸色一黑、气笑了 |
| 恐惧 | 背脊发寒 / 头皮发麻 | 心里发毛、腿有点软 |
| 得意 | 嘴角微微上扬 | 他乐了、哼了一声 |
| 说话动作 | 缓缓开口道 / 沉声道 | 开口就说、接话道 |
| 内心 | 他心中暗道 / 脑海中闪过 | 他寻思、想了想 |
| 不是A而是B | 这不是结束，而是开始 | 说白了就是… / 删点题壳 |
| 突然转折 | 下一秒 / 就在这时 | 紧接着、忽然、结果 |
| 出场 | 一道身影缓缓走来 | 人进来了、门口站着个人 |

## 五、输出契约：`_humanized` 后缀（硬性）

凡执行**本节对照库替换**（含「去 AI 味」文件模式默认启用对照库时）：

0. **改前备份（先于任何写出）**：将当前输入章节原样复制到同目录 `_revision-backups/{stem}_原稿_pre-deslop_{YYYYMMDD}{ext}`（同日冲突追加 `_{HHmm}`；目录不存在则创建）。文件名须含 `_原稿_`。检测档不备份。备份失败则停止改写。报告写明备份路径，便于后期 diff 去味前后。
1. **默认写出人味文件（单独调用）**。读入 `path/to/第N章.md`（或任意章节正文），写出同目录：
   - `path/to/第N章_humanized.md`
   - 规则：`{stem}_humanized{ext}`。例：`03.md` → `03_humanized.md`；`foo.正文.md` → `foo.正文_humanized.md`。
2. 若输入路径的 stem **已以 `_humanized` 结尾**：在该文件上更新（视为再人味），不再叠套 `_humanized_humanized`。再人味前仍按第 0 步备份**当前**文件内容（文件名用当前 stem，避免冲掉更早的 pre-deslop 备份）。
3. Phase 4 脚本（`check-ai-patterns.js` / `check-degeneration.js` / `normalize-punctuation.js`）对 **人味产物**跑，不对未改原稿跑（除非用户只要检测原稿）。写后定稿模式在覆盖后，对**正式正文路径**再复扫一次。
4. 报告必须写明：`原文件`、`改前备份`、`人味文件`、`对照库:已执行`（或用户豁免）、扫描句数、精确 map 命中/替换、**语义对齐**命中/替换、`{xx}` 回填数、未替换/`[需复核]` 数。替换数可为 0，但须有语义扫描结论。产物中**不得残留** `{xx}`。缺 `对照库:已执行` → 整次去味判未完成。
5. **例外 A（须用户原话）**：用户明确说「原地改 / 覆盖原稿 / edit in place」时，可直接改原文件；**仍须先完成第 0 步备份**；检测档不写文件。
6. **例外 B（写后定稿模式，硬步骤）**：由 `story-long-write` / `story-short-write` 写正文后同轮触发，或用户说「定稿覆盖 / 写后去味 / 最终正文」时——在完成对照库 + Gate 并得到人味结果后，**必须**将人味内容覆盖回正式正文路径（长篇 `正文/第XXX章_*.md`，短篇 `正文.md`）。覆盖后该路径才是最终正文。报告须含 `定稿覆盖:已执行`。中间 `_humanized` 可移入 `_revision-backups/`，避免双正文。缺定稿覆盖 → 写流程不得宣称本章/本稿已交付。

文本模式（粘贴片段、无路径）：仍回传润色全文，不强制落盘；若用户同时给了保存路径，按上述命名写 `_humanized` 文件（有路径则同样先备份）。
