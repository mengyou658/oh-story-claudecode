# 本仓库生产硬规则（本地 skill 覆盖）

> 仅适用于本仓库 `skills/` 下的长篇写作链路。与上游/全局 skill 冲突时，**以本文件为准**。

---

## 0. 大纲 / 细纲冲突配额（硬约束）

与 `workflow-setup.md` Phase 3、`story-outline` 规则 0 / 0b 一致；与上游冲突时以本条为准。

- **大纲生成要求：其中包含三次大两难性时刻以及20个小的冲突(可以是自我或者外部爆发升级反转或者处理)以及一个清晰的道德前提**
  - 写入 `大纲/大纲.md`「道德前提与冲突配额」；缺项不得批产细纲。
- **细纲生成要求：每章节都有一个小冲突(可以是自我或者外部爆发升级（反转或处理或打脸或突然想起重要的事情忘记处理或者其他的冲突）)**
  - 每章细纲必填「本章小冲突」；`check-outline-contract.js` 将该字段列为结构必填。

## 1. 开书：标题脑洞 ×3 + 三选一杂糅

Phase 2 定书名前必须执行（用户已给定唯一书名且书面确认可跳过脑洞扩量，但仍须做「三卖点杂糅」登记）：

1. **产量**：若惯例/用户未指定数量，默认生成 **3** 个书名候选 → 实际生成 **×3 = 9** 个；用户说「给 N 个」→ 生成 **3N** 个。技法见 `genre-readers.md`「书名命名技法」。
2. **脑洞描述（强制）**：每个候选**不得只给书名**。须附 **1–3 句脑洞描述**，说清：这本书在卖什么 / 核心钩与兑现点 / 适合前期·后期·贯穿哪一类。推荐表格列：`# | 书名 | 命名切口 | 脑洞描述`。
3. **选择**：用 AskUserQuestion（或等价多选）让用户从候选里**选出 3 个**（可改写后再选）。
4. **杂糅进同一本书**（写入 `设定/题材定位.md` 或核心设定表「书名卖点分配」）：
   - **前期卖点**：选自中的 1 个 → 开篇/黄金三章主兑现
   - **后期卖点**：选自中的 1 个 → 中后段高潮/终局兑现
   - **贯穿卖点**：选自中的 1 个 → 全书主线/金手指/身份线持续兑现
5. **对外书名**：三选中再定 1 个作为目录名与封面用书名；另两个仍作为卖点义务，不得写丢。落盘时保留对应脑洞描述，避免只剩空书名。

## 2. 写正文：默认 3 章细纲 → 1 章正文

| 正文章号 B | 消费的细纲章号 |
|-----------|----------------|
| 1 | 细纲 1–3 |
| 2 | 细纲 4–6 |
| N | 细纲 `(3N-2)`–`(3N)` |

- 写「正文第 N 章」时：**一次读取并合并**对应 3 份细纲的批准情节，压成**一篇**紧凑正文；不过场注水、不把三章细纲写成三章正文。
- 用户书面要求「一纲一章」时可覆盖本默认。
- 日更说「写 2 章正文」= 消费 **6** 章细纲；说「日更 3 章」默认指 **3 章正文**（9 章细纲），除非用户点名细纲章号。

### 追踪必须双进度

每次正文提交后更新 `追踪/章号映射.md`（权威人工可读映射；与 `_tracking-state.json` 并行）：

```markdown
# 章号映射
- 正文已写到：第{B}章
- 细纲已消费到：第{M}章（M = 3B）
- 最近映射：正文第{B}章 ← 细纲第{A}–{C}章
```

同时在本章 `逐章记录` 的 `result` 或近章速记中写清同一映射句。`上下文.md`「当前位置」汇报时口头/书面同时报：**正文第几章 / 细纲消费到第几章**。  
`last_committed_chapter` 仍表示**正文**章号。

## 3. 字数与节奏

- **不按目标字数生成**：批准情节写完即停；细纲「字数目标」与 ±12%/±15% 带**只作规划/测量参考，绝不追写**。
- **生成多少就是多少**：不以 2000、目标带或任何下限为由加厚、补写、合并或请用户「接受更短」。
- **比 2000 少也不加厚**：情节已齐时直接 `accept-current-length`；禁止用水话回填，也禁止为凑字扩写已批情节点。
- 人味/去AI/净删后字数少了就少了——**可接受**。
- 文风优先**紧凑快节奏**；过场一句带过。
- **独立字数账本**（与 tracking 并行，不进正文）：每章定稿后写入 `追踪/字数记录/第XXX章.md`，只记 `visible_chars_v1` 实际字数与正文路径；不据此触发改写。

字数细则执行面：`workflow-chapter.md`「字数测量权威」、`long-format.md`「长篇章级约束」。

---

## 4. 写正文后必须同轮 story-deslop（最终正文＝去味后）

> 未去味的落盘稿只是中间产物；**`正文/第XXX章_*.md` 必须是去味后的定稿**。

1. **同轮硬步骤**：每章正文首次写入 `正文/` 后，**不得**先汇报「写完」或进入下一章；必须在**同一轮**立即执行 `story-deslop` 全流程（定档清理 → 改前备份 → 对照库精确 map + 逐句语义对齐 → Gate → 确定性收尾）。只跑 `check-ai-patterns.js` / `normalize-punctuation.js` **不算**完成。
2. **定稿覆盖**：去味完成后，**必须**用人味结果覆盖回正式正文路径 `正文/第XXX章_*.md`。覆盖后的该路径才是最终正文；字数账本、chapter check、tracking commit、上一章承接均以该路径为准。
3. **备份与中间件**：改前原稿进 `_revision-backups/{stem}_原稿_pre-deslop_{YYYYMMDD}{ext}`；中间 `{stem}_humanized{ext}` 写完并验收后，可保留在同目录或移入 `_revision-backups/`，**不得**与正式正文并列成「双正文」导致 chapter check 歧义。
4. **唯一豁免**：用户显式说「本章不去味/跳过检查」——在标题行下加 `<!-- 去味:跳过 -->`。除此之外，Fallback / Cursor / solo **不得**跳过本步。

执行面：`workflow-chapter.md`「写后同轮清零」+ `skills/story-deslop/SKILL.md`「写后定稿模式」。
