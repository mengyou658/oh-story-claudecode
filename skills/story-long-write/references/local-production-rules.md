# 本仓库生产硬规则（本地 skill 覆盖）

> 仅适用于本仓库 `skills/` 下的长篇写作链路。与上游/全局 skill 冲突时，**以本文件为准**。

---

## 1. 开书：标题脑洞 ×3 + 三选一杂糅

Phase 2 定书名前必须执行（用户已给定唯一书名且书面确认可跳过脑洞扩量，但仍须做「三卖点杂糅」登记）：

1. **产量**：若惯例/用户未指定数量，默认生成 **3** 个书名候选 → 实际生成 **×3 = 9** 个；用户说「给 N 个」→ 生成 **3N** 个。技法见 `genre-readers.md`「书名命名技法」。
2. **脑洞描述（强制）**：每个候选**不得只给书名**。须附 **1–3 句脑洞描述**，说清：这本书在卖什么 / 核心钩与兑现点 / 适合前期·后期·贯穿哪一类。推荐表格列：`# | 书名 | 命名切口 | 脑洞描述`。
3. **选择**：用 AskUserQuestion（或等价多选）让用户从候选里**选出 3 个**（可改写后再选）。
4. **杂糅进同一本书**（写入 `设定/题材定位.md` 或核心设定表「书名卖点分配」）：
   - **前期卖点**：选自中的 1 个 → 开篇/黄金三章主兑现
   - **后期卖点**：选自中的 1 个 → 中后段高潮/终局兑现
   - **贯穿卖点**：选自中的 1 个 → 全书主线/金手指/身份线持续兑现
5. **对外书名**：三选中再定 1 个作为目录名与封面用书名；另两个仍作为卖点义务，不得写丢。落盘时保留对应脑洞描述，避免只剩空书名。

---

## 2. 写正文：默认 3 章细纲 → 1 章正文

| 正文章号 B | 消费的细纲章号 |
|-----------|----------------|
| 1 | 细纲 1–3 |
| 2 | 细纲 4–6 |
| N | 细纲 `(3N-2)`–`(3N)` |

- 写「正文第 N 章」时：**一次读取并合并**对应 3 份细纲的批准情节，压成**一篇**紧凑正文；不过场注水、不把三章细纲写成三章正文。
- 用户书面要求「一纲一章」时可覆盖本默认。
- 日更说「写 2 章正文」= 消费 **6** 章细纲；说「日更 3 章」默认指 **3 章正文**（9 章细纲），除非用户点名细纲章号。

### 追踪必须双进度

每次正文提交后更新 `追踪/章号映射.md`（权威人工可读映射；与 `_tracking-state.json` 并行）：

```markdown
# 章号映射
- 正文已写到：第{B}章
- 细纲已消费到：第{M}章（M = 3B）
- 最近映射：正文第{B}章 ← 细纲第{A}–{C}章
```

同时在本章 `逐章记录` 的 `result` 或近章速记中写清同一映射句。`上下文.md`「当前位置」汇报时口头/书面同时报：**正文第几章 / 细纲消费到第几章**。  
`last_committed_chapter` 仍表示**正文**章号。

## 3. 字数与节奏

- **硬合格线**：每章正文 **≥2000 字**（`visible_chars_v1`）即符合字数要求。
- 细纲「字数目标」与 ±12%/±15% 带**只作规划参考，不强制符合**。
- 人味/去AI/净删后字数少了就少了——**可接受**。
- **禁止用水话回填**（灌描写、铺垫、氛围、内心独白、无功能动作凑目标或凑回原稿长度）。
- 文风优先**紧凑快节奏**；过场一句带过。
- 相对目标 `under` 但实际 ≥2000 → `accept-current-length`；仅 **<2000** 且情节已齐才考虑合并相邻两章正文（并回写映射）。

字数细则执行面：`workflow-chapter.md`「字数测量权威」、`long-format.md`「长篇章级约束」。
